# 漏洞复测报告生成

## 触发条件

对话中已完成漏洞复测，用户要求生成复测报告时触发。

> 此 skill 只负责**报告生成**。漏洞信息的提取方式（.docx/.md/对话）由调用方处理，不在本 skill 范围。

## 与 pentest-report 的区别

| | pentest-report | retest-report |
|---|---|---|
| 用途 | 首次渗透测试发现 | 验证已有漏洞是否修复 |
| 结构 | 业务分析 + 漏洞清单 + 攻击链 | 复测概况 + 逐项详情 + 汇总 |
| 侧重点 | 技术栈、API、认证、攻击路径 | 复测过程记录、可达性、修复状态 |

## 报告结构

```
1. 标题 + 元信息（日期、来源）
2. 复测概况表
3. 漏洞复测详情（每个漏洞一个小节）
   - 基本信息表（等级/单位/地址/参数/类型/Payload）
   - 复测过程（分步骤记录）
   - 复测结论（blockquote）
   - 修复建议（ul）
4. 复测汇总表
```

## 工作流程

### 阶段 1：提取复测数据

从当前对话中提取每个漏洞的以下信息：

| 字段 | 说明 |
|------|------|
| 涉及单位 | 单位全称 |
| 漏洞类型 | SQL注入 / XSS / 文件上传 / 命令执行 / SSRF |
| 原始等级 | 高危 / 中危 / 低危 |
| 目标地址 | 完整 URL（含端口和路径） |
| 注入参数 | SQLi 的参数名（如不适用则省略） |
| 原始 Payload | 报告中的攻击 payload（有则记录） |
| 复测步骤 | 连通性、HTTP 可达性、工具执行的过程和输出 |
| 复测结论 | 已修复 / 仍存在 / 不可达 / 无法验证 |
| 修复建议 | 针对性的加固建议 |

### 阶段 2：生成 MD 报告

按阶段 1 提取的数据，填充以下模板，文件命名：`{来源简称}_复测报告_{YYYYMMDD}.md`

```markdown
# {来源名称} — 漏洞复测报告

**复测日期**: YYYY-MM-DD
**报告来源**: {周报/文件名/对话描述}
**复测结论**: {一句话总结}

---

## 复测概况

| 项目 | 内容 |
|------|------|
| 原始漏洞数 | N |
| 可复测漏洞数 | N |
| 已修复/下线 | N |
| 复测结论 | 通过 / 部分修复 / 未修复 |

---

## 漏洞复测详情

### 漏洞 #N: {漏洞名称}

| 字段 | 内容 |
|------|------|
| 原始等级 | **高危** |
| 涉及单位 | ... |
| 目标地址 | `http://...` |
| 注入参数 | `param` |
| 注入类型 | ... |
| 原始 Payload | `...` |

#### 复测过程

1. **连通性测试** (时间)
   - `ping` → 100% 丢包 / 可达
   - TCP 端口 (80/443/8080) → 全部超时 / 开放
2. **HTTP 可达性** → 连接超时 / 200 OK
3. **工具复测** → sqlmap 未执行（目标不可达）/ 执行结果

> **复测结论**: ...（用 blockquote 格式）

#### 修复建议

- ...
```

### 阶段 3：生成 HTML 报告

用阶段 2 生成的 MD 报告替换 `assets/template.html` 中的占位符，输出 `.html` 文件。

| 占位符 | 填充内容 |
|--------|---------|
| `{TITLE}` | 报告标题 |
| `{WEEKLY_NAME}` | 来源名称 |
| `{RETEST_DATE}` | YYYY-MM-DD |
| `{SOURCE_FILE}` | 来源文件名或描述 |
| `{OVERALL_CONCLUSION}` | 总体结论一句话 |
| `{OVERVIEW_TABLE_ROWS}` | 概况表 `<tr>` 行 |
| `{VULN_DETAIL_SECTIONS}` | 所有漏洞详情 HTML 拼接 |
| `{SUMMARY_TABLE_ROWS}` | 汇总表 `<tr>` 行 |
| `{GENERATED_TIME}` | YYYY-MM-DD HH:MM |

> 等级标签：高危用 `<span class="tag-high">高危</span>`，中危用 `<span class="tag-medium">中危</span>`，低危/通过用 `<span class="tag-pass">低危</span>`

## V1 配色

| 元素 | 颜色 | 用途 |
|------|------|------|
| `--blue` | `#1a56db` | 标题、表头、左边框 |
| `--blue-light` | `#e8f0fe` | 结论框背景 |
| `--text` | `#333` | 正文 |
| `--text-secondary` | `#666` | 元信息、页脚 |
| `--border` | `#e0e0e0` | 表格边框、分隔线 |

| `--zebra` | `#fafafa` | 表格偶数行 |
| `--danger` | `#d93025` | 高危标签 |
| `--success` | `#188038` | 通过/低危标签 |
| `--quote-bg` | `#fffde7` | 复测结论引用块背景 |

CSS 变量已在 `assets/template.html` 中定义，生成 HTML 时直接使用模板即可。

## 注意事项

- 此 skill 仅负责报告生成，不负责漏洞提取——漏洞信息必须已在对话中
- 无复测过程的漏洞不要出现在报告中
- 输出始终 MD + HTML 双版本
- 不要为了凑数编造漏洞或复测步骤
