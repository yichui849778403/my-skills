# 中文演讲备注润色

## 何时使用

用户拿着 PPT 备注（逐字稿）来求助，抱怨以下任一情况：

- "AI 润色后我越念越快"、"念着尴尬"、"每句都是独立观点"
- "翻译腔"、"AI 腔"、"不符合中文习惯"
- "太活泼/太女孩子"、"太教条"、"太公文"
- 需要慢速引导型节奏（有呼吸、有画面）
- 上台不熟练，需要备注自带讲述意图引导

**不要用于**：写幻灯片正文、写文章、写公文、写营销文案。这些场景需要的是书面语，不是演讲口语。

## 核心原则

**书面语和演讲口语是两个相反的方向**。AI 默认的"润色"往书面走（更流畅、更专业、更紧凑），而演讲备注需要往口语走（更慢、更松、更多停顿、更多具体画面）。用户抱怨"AI 润色后越念越快"，本质是 AI 把教条稿改成了密度更高的书面稿，抽掉了念稿人需要的骨架。

**不要在 AI 原稿上迭代**——每次改都会保留 AI 味的骨架。**跳出来，从"一个真人怎么讲这个故事"出发，从头重写**。

**TTS 顺 ≠ 人念顺**。TTS 能流畅朗读的句子，人念起来可能舌头打结（翘舌+后鼻密集、"的着"堆叠、拖腔接前鼻音收尾）。以"人念"为标准，不是"AI 朗读"为标准。

**故事页和观点页分工**：故事页讲到位就停，不硬加观点/升华；观点页承接故事，拆解分析，落到具体动作/原则。硬把观点塞进故事页尾巴，是最常见的 AI 病。

**密度 > 字数**：真正的问题不是字数，是"每句都是独立观点"。如果每句都是简单句、一句一行、一个意思，长一点也能念得慢；如果每句都是复杂句、嵌套定语、长排比，短也会念得喘不过气。字数是信号，不是目的——写完默念一遍，如果感觉"每句都在赶"，就是密度过高，需要拆句或合并子点，而不是机械砍字。

## 第一原则：简单句 > 口语词汇

**这是最容易搞错的一条**。演讲备注的核心是**句子短、一句一个意思**，不是把书面词全换成口语词。

- ✅ "开通账号时，同时设定一个有效期，到期后自动失效。" —— 词汇书面（"设定"、"有效期"、"自动失效"），但句子简单，念起来顺
- ❌ "开通的时候，顺手设个有效期，到期自动失效。" —— 词汇口语（"顺手设个"），但**没必要**，原句已经够简单

**判断标准**：这句话能不能**一句一行**写出来？如果需要拆成两行，就是太长了。

**真正该改的是句式，不是词汇**：

- 复杂句式 → 简单句式："既然是...就..." → "本来就是...就..."；"即使...也..." → "就算...也..."
- 长排比 → 短排比："谁来提出申请，谁来审批，谁来确认第三方已经完成工作，谁来执行账号回收" → "谁提的、谁批的、谁去删"
- 嵌套定语 → 独立短句："一个已经失去业务必要性的外部账号，仍然会留在系统里" → "这个账号，本来就不该留着。还留在系统里，早晚是个入口"

**独立短句做节奏点**：七个字以内、独立成行的短句，是讲者最有力的武器。

- "要解决也 很简单。"
- "这时，问题来了。"
- "往深里看，问题不止在密码上。"

**词汇保留书面语的场景**：技术术语（"自动失效"、"重新审批"、"有效期"）、客户场合的正式度需要、幻灯片上就有的关键词——这些**不要**强行口语化。

## 硬规矩（必须遵守）

1. **密度 > 字数**：真正的问题不是字数，是"每句都是独立观点"。如果每句都是简单句、一句一行、一个意思，长一点也能念得慢；如果每句都是复杂句、嵌套定语、长排比，短也会念得喘不过气。**检查密度，不是检查字数**——写完默念一遍，如果感觉"每句都在赶"，就是密度过高，需要拆句或合并子点。
2. **反问克制**：一页最多一个，或者不用。多用陈述句。反问连续用会显得表演性强、"太女孩子"。
3. **故事页不硬加观点/升华**：讲到位就停。收尾落在具体画面/具体动作/具体评价，不做"XX 至关重要"、"安全意识需要提升"这种抽象升华。
4. **不用硬标签**：【现象】【排查】【真相】、"第二节"、"接下来我们讲"——都是给读者看的，不是给念稿人用的。
5. **不用（停一下）标记**：呼吸点应该自然长在句子里（"后来才发现"、"其实"、"刚好"这些词本身就是停顿），不需要显式标注。
6. **不列举排查/操作细节**：真人讲"进行了排查"，AI 才讲"逐项检查了端口、配置、日志、系统调用等"。列举会让节奏拖沓，观众记不住。
7. **每页 1-2 个主动作**：一页讲清楚一件事就够了。多了就是密度过高，念稿人会失控加速。
8. **一句一行**：每个句子独立成行（用空行分隔）。视觉空格就是呼吸点，比"（停一下）"标记自然得多。如果一个句子长到需要换行才能读完，就是要拆的信号。

## 中文口语手法清单

### 语气副词（铺满）

"其实"、"才"、"刚好"、"倒是"、"结果"、"就"、"却"、"到底"、"总归"、"可能"、"通常"

一页里至少 3 个以上语气副词，节奏才慢得下来。

### 中式连接结构

- **"后来才发现..."** —— 转折揭秘
- **"这时，问题来了。"** —— 独立短句做悬念节点（讲者节奏，AI 想不到）
- **"因为...所以..."** —— 明确因果铺陈（不追求简洁）
- **"一...就..."** —— 连贯动作
- **"不仅...还能..."** —— 递进
- **"但往深里看..."** —— 视角切换
- **"那如果..."** —— 假设（克制使用，一页最多一次）

### 指代与重复

- **指代不明但口语化**："那个系统里"、"这么个账号"、"这套平台"——人说话不精确指代，AI 会写成"该业务系统中"
- **重复关键词做话题衔接**：宁可啰嗦也要清晰。"这个短信验证码，就是..."（不是"它就是..."）。AI 会为了避免重复用代词简化，反而让观众跟不上
- **方位表达代替所有格**："厂商那边" > "厂商的平台"；"设备背后" > "设备的后端"；"系统里" > "系统内部"

### 四字格节奏（用户强偏好）

中文口语的天然节奏单位是四字格（两个双音节词拼成四字），念起来有稳定的"哒哒-哒哒"拍子。优先用四字收尾：权限管理、自动关停、回收流程、提交工单、盖章申请、审批通过。**避免三字碎收尾**：管起来、想清楚、跟着关——节奏碎，念着不顺。

### 动词与补语

- **具体动词代替抽象动词**："进了后台" > "获得了系统访问权限"；"开了个账号" > "创建了账户"；"删掉" > "进行删除操作"
- **动词+补语+"一点"**："改复杂一点"、"设得比较简单"、"传下去"、"落到...手里"、"撤了场"
- **完成态"了/出来的/到了/过的"**：中文自然节奏，不是冗余
- **重叠词**："一项一项排查"、"一级一级传下去"、"通不通"、"好不好用"、"干干净净"（活泼场合可用）

### 讲者视角

- **第一人称"我/我们"**："我在一次安全检查中遇到的"、"我们得有一套流程"——个人化经历比机构叙事可信
- **"我们以为..." 包含观众**：比"他们就认为..."谦卑，把观众拉进来一起承担认知误区
- **允许讲者评价**："这家比较倒霉"、"这种情况其实很多单位都有"——**具体评价**，不是抽象判断
- **元叙述插入**："这里简单说明一下，AC 就是..."——直接告诉听众"我要插一句解释"，不用反问自答（"AC 是什么？就是..."太活泼）

### 收尾手法

- **回到具体画面**："哪天当时的第三方人员想起来，回来登一下，账号还在那儿，密码也还是原来那个，直接就能进后台"
- **具体评价落地**："这家比较倒霉，红队攻破平台后，刚好通过平台，远程控制了他们的 AC"
- **故事页可以戛然而止**："我们以为把密码改复杂一点，就解决了问题。" 就停这里，观点交给下一页
- **观点页落到具体清单**：五步、五原则、三个动作——对应幻灯片视觉，念的时候手可以指屏幕
- **不做抽象升华**：不写"权限管理至关重要"、"安全意识需要提升"、"这给我们的启示是..."

## 反例：AI 腔特征清单

看到以下结构，一律重写：

| AI 腔         | 中文口语改法                        |
| ------------ | ----------------------------- |
| 对...进行...    | 直接动词（"排查" 不是 "进行排查"）          |
| 为...提供...接入  | "给内部提供 WiFi" 或 "内部 WiFi 都从它走" |
| 一旦...随即...   | 一...就...                      |
| 落入...手中      | 落到...手里                       |
| 逐项排查         | 一项一项查 / 全查了一遍                 |
| 正是           | 就是                            |
| 逐级下发         | 一级一级传下去                       |
| 全部被接管        | 一台也保不住 / 一台不落                 |
| 具备...能力      | 能...                          |
| 进一步核查确认      | 后来才发现 / 后续核查才发现               |
| 名义上...实际上... | 名字叫...其实是...                  |
| 表面现象/根本原因    | 表面上看/往深里看                     |
| 该业务系统中       | 那个系统里                         |
| 未发现异常        | 没查出问题 / 一个漏洞都没找着              |

## 声音友好性检查

写完默念一遍，标注以下"舌头打结"点：

**翘舌+后鼻密集**（连在一起念会打结）：

- 现成的、一层层、就这样、顺着通道、全部沦陷、落到手中、逐级下发

**"的/着"堆叠**（一句话超过 2 个就要拆）：

- 连着这套平台的设备
- 厂家预留的管理通道
- 所有接入的设备的远程管控能力

**拖腔接前鼻音收尾**（语气掉不下来）：

- "就这样，全部沦陷"（yàng + lún xiàn）
- "一级级往下传"（chuán 收尾弱）

**儿化+翘舌**（念快了含糊）：

- 一层层、这样、有点儿

**修法**：

- "现成的" → 删掉，或改"厂家留的"
- "一层层" → "一级一级"
- "就这样" → 删掉，或改"结果"
- "沦陷" → "被拿下" / "保不住" / "失守"
- "顺着通道" → "沿着这条通道" 或直接删

## 工作流

### 收到润色请求时

1. **先问场景**：客户是谁？正式度？讲者经验？场合（内训/客户交付/大会演讲）？
2. **要样本**：让用户提供 1-2 页"念得顺"的原稿作为风格锚点。如果用户已经有自己的口语版本，那是最好的样本
3. **不要立刻动手**：先分析样本的特征（编号骨架？口语连接词？动词类型？讲者评价频率？）
4. **诊断原稿问题**：字数、AI 腔结构、声音打结点、抽象升华、反问密度

### 写每一页时

1. **读懂幻灯片正文**：备注是配合视觉的，不能脱离。检查幻灯片上的关键词、编号、图表，备注要呼应
2. **提取核心信息点**：这页要传达的 1-2 个主动作
3. **从头重写**：不看 AI 原稿的措辞，只看事实点
4. **对照手法清单**：语气副词（≥3）、连接结构、指代重复、动词补语、讲者视角、收尾手法
5. **声音测试**：默念一遍，标注打结点
6. **检查是否踩硬规矩**：反问 ≤1、无（停一下）、无硬标签、无抽象升华

### 交付时

给用户看：

1. **润色后的稿子**（完整、可直接用、字数标注）
2. **做了什么**（3-6 条具体的手法说明，最好带"我的旧版 vs 新版"对比表）
3. **2-3 处可调整点**（让用户主动介入，避免"完美交付"陷阱——用户往往有场合/客户偏好，需要微调）
4. **询问是否继续下一页**（不要一次交付多页，节奏错了浪费；用户点头再往下推）

### 迭代时

用户反馈后：

- **不要辩护**：直接承认差距，具体指出用户版好在哪
- **提炼规律**：把用户的修改抽象成可复用的写作原则（更新到 memory 或本 skill）
- **应用到下一页**：让用户看到"你听懂了"
- **不要过度道歉**：一次承认就够，重点放在下一版怎么改

## 常见陷阱

- **越改越像"漂亮的 AI 稿"**：在 AI 原稿基础上迭代，会保留 AI 味的骨架。必须跳出来重写
- **加"讲故事大叔"味**：用"真事儿"、"翻了个遍"、"干干净净"、"是不是...呢？"——太活泼，不适合沉稳场合（客户交付、政企培训）
- **加公文腔**：用"逐项排查"、"进一步核查确认"、"正是"、"综上所述"——太书面，不像人讲话
- **强行加悬念**：反问、破折号、"（停一下）"、"你猜怎么着"——表演性太强，观众会尴尬，讲者会加速
- **每页都要"给出观点"**：故事页硬加收尾升华，反而破坏了叙事节奏。观点页才输出观点
- **删掉重复关键词**：为了避免啰嗦而用代词简化，反而让观众跟不上
- **忽略幻灯片视觉**：备注讲的和幻灯片显示的对不上，观众眼神会漂
- **一次交付多页**：风格没定就批量做，改起来成本大。先出一页样板，用户点头再往下
- **把"口语化"理解成"换词汇"**：将 "设定" 改成 "设个"、"审批" 改成 "批一次"、"留在" 改成 "挂在"——这是**错的**。真正的问题是**句子结构复杂**（长排比、嵌套定语、"既然是...就..."），不是词汇书面。先拆句子，再看词汇。如果句子已经够短，书面词（技术术语、客户场合正式词、幻灯片关键词）**保留不动**

## 验证清单

一页稿子写完后，自检 9 项：

1. **一句一行**？每个句子独立成行，视觉空格就是呼吸点
2. **反问** ≤ 1 个？
3. **是否有"AI 腔特征清单"里的结构**？（对...进行、正是、一旦...随即、逐项、综上所述...）
4. **是否有"复杂句式"**？（既然是...就...、即使...也...、长排比、嵌套定语）—— 有就拆
5. **默念一遍，是否有舌头打结点**？（翘舌+后鼻密集、"的着"堆叠）
6. **默念一遍，是否感觉"每句都在赶"**？—— 如果是，密度过高，需要拆句或合并子点
7. **收尾是具体画面/动作/评价，还是抽象升华**？
8. **是否用了 3 个以上语气副词**？（其实/才/刚好/就/却/可能/通常）
9. **是否有独立短句做节奏点**？（学"这时，问题来了。"、"要解决也很简单。"的手法，一页 1-2 处）

**9 项全过，交付**。任何一项不过，回去改。

## 参考样本（用户认可的沉稳风格）

**故事页收尾**（p41，讲到位就停，不输出观点）：

> 后来，在一次网安行动中，这个账号 被发现了。  
> 因为是弱口令，所以 这家单位 收到了通报。  
> 这时，问题来了。  
> 拿到通报后，通报写的是"弱口令"，所以整改的时候，我们以为 把密码 改复杂一点，就 解决了问题。

**关键手法**：

- "这时，问题来了。" 独立短句做悬念节点
- "通报写的是..." 重复"通报"两次做话题衔接
- "我们以为..." 包含观众的谦卑视角
- 结尾戛然而止，观点交给下一页

**观点页收尾**（p42，落到具体清单）：

> 所以对外部人员的这种临时权限，我们得有一套完整的生命周期，从开通一直管到删除。  
> 具体分五步：申请、审批、使用、复核、回收。  
> 对应的原则，也是五个：实名开通、最小权限、限定时间、操作留痕、到期回收。

**关键手法**：

- "我们得有" 用"得"字比"需要"沉
- "从开通一直管到删除" 用具体动作解释"生命周期"这个术语
- 落到具体数字（五步、五个原则），对应幻灯片视觉

**故事转折**（p43，用户亲手改写版）：

> 技术人员 到场后 进行了 排查，但 没有找到 漏洞。  
> 后来才发现，问题，其实 出在了 厂商那边。  
> 大家 连 WiFi 时，会收到 一条 短信验证码。  
> 这个 短信验证码，就是 厂商那边的 平台 发出来的。

**关键手法**：

- "进行了排查"—— 不列举端口/配置/日志
- "后来才发现，问题，其实出在了厂商那边"—— 三个语气副词连用（才/其实/了）+ 方位表达（那边）
- "这个短信验证码"—— 重复前一句关键词做话题衔接
- "厂商那边的平台"—— 方位+所有格混用，非常口语

**观点页·简单句范本**（p42，用户亲手定稿）：

> 这个案例，表面上看，是弱口令。
>
> 实际上是 测试账号 没有及时 删除。
>
> 所以，光改密码 是不够的。
>
> 要解决也 很简单。
>
> 开通 账号时，同时设定 一个 有效期，到期后 自动失效。
>
> 如果 确实要 继续使用，再 重新 申请、重新 审批。
>
> 这样，就算 忘了处理，账号 也不会 一直留在 系统里。

**关键手法**（"简单句 > 口语词汇" 的最佳示范）：

- **一句一行**：每个句子独立成行，视觉空格就是呼吸点
- **词汇保留书面语**："同时设定"、"有效期"、"自动失效"、"重新审批" —— 技术术语和正式词**不强行口语化**
- **独立短句做节奏**："要解决也 很简单。" 七个字砸下来
- **连接词极简**："所以"、"如果"、"这样" —— 不用 "既然是...就..."、"即使...也..."
- **内容聚焦**：幻灯片上有"三个管理缺口 + 五个原则"，备注**只挑最实用的一条**（有效期）讲透。观众听完能立刻去做的，就这一件事
