# 终端木马事件处置 · 现场留痕

## 适用场景

客户单位被上级（网信办等）通报中了木马，本单位没有 EDR/态势感知等可溯源设备，
已在防火墙封禁木马控制 IP，只能逐台终端杀毒。需要证明"这件事确实做过"。

典型约束（先确认，它们决定方案形态）：

1. **拿不到签字** —— 乙方上门服务，甲方员工不会逐台签"认责"；
   使用人常常不在工位，部门负责人也不愿签。默认按**零签字**设计。
2. **杀毒软件不统一** —— 客户机器各装各的个人版（360/火绒/电脑管家/Defender），
   没有集中管控平台，日志格式各异、多数不能导出。
3. **机器老旧** —— 常见 Win7（PowerShell 2.0）到 Win11 混合，32/64 位都有。

## 核心思路：不靠签字，靠"机器自证 + 影像自证"

证据锚点放在三个我方完全可控的东西上：

| 锚点 | 作用 |
|---|---|
| 脚本自动采集的主机标识 | 计算机名 / IP / MAC / 时间由机器自己报告，不经过人手抄 |
| 截图 + 烧录水印 | 把编号、门牌号、计算机名、IP、时间直接画进图像像素，事后无法分离 |
| 自动生成的台账 CSV | 一行一台，不用手抄、不用整理，直接可交 |

**不要依赖**：杀软界面的检出一致性（各版本差异大）、使用人签字、客户配合录入。

**不要在客户机上留任何文件** —— 省得落"乙方在甲方机器上写东西"的话柄。
所有产出只落 U 盘，当天务必另备份一份。

## 现场采集脚本

`scripts/scan-record.ps1` + `scripts/运行.bat`（双击运行）。

单台流程：人工用杀软全盘扫描 → 停在扫描结果界面 → 双击 `运行.bat`
→ 输入门牌号（脚本按对照表查出部门）→ 回车确认几项 → 提示后按回车
→ 窗口自动最小化、2 秒后截屏 → 顶部烧录水印 → 存 `截图\` + 追加台账行。

**脚本不能操作杀毒软件查杀**：个人版杀软没有对外统一的命令行接口
（只有 Windows Defender 有 `MpCmdRun.exe`，但客户装的多半不是它）。
查杀必须人工点，脚本只负责记录和取证。

关键可调参数（在 ps1 顶部）：`$Operator`（执行单位名）、`$WaitSec`（默认 2）、`$FontName`、`$BarHeight`。

### 台账字段

门牌号、部门、使用人、网络类型、IP地址、MAC地址、hostname、排查时间、
查杀工具、检测结果、处置结果、截图文件、备注

- 网络类型固定"互联网"
- IP/MAC 取**能上外网的那块网卡**：有默认网关 + 非虚拟网卡 + 跃点数最小
- 检测结果只留 `发现木马` / `未发现异常`；处置结果自动推导（发现木马→清除成功，未发现→正常）
- 查杀工具手输，默认取台账上一台填过的值 —— 第一台输一次，后面几十台直接回车

### 机器 ↔ 部门 的对照表

客户通常已有一份电脑统计表（门牌号、部门、姓名、IP、MAC、hostname…）。
从中导出 `终端对照表.csv`（列名用英文 `room,dept,user,hostname,ip,mac` 更稳），
脚本按门牌号查部门。

**重要**：
- **不要按 hostname 匹配使用人** —— 人员流动大，同一台机器今天 A 用明天 B 用。
  让操作人输门牌号，使用人留空、现场问到再填。
- 一个门牌号应对应唯一部门。导出前先查"一门多部门"，有冲突**先问用户哪个名字才准**，
  不要自己替用户假设哪一行是对的（这里踩过坑，方向搞反过一次）。
- 出门牌号分布（按楼层/部门分组）能帮用户排现场计划。
- 导出时对已知的名称笔误做统一替换，避免源表笔误影响脚本。

## PowerShell 2.0 兼容清单（Win7 裸机必看）

Win7 自带 PS 2.0，以下写法在 PS2 上**会直接报错**，必须避开：

| 不能用（PS3+） | 换成（PS2 可用） |
|---|---|
| `Import-Csv -Encoding` / `Export-Csv -Append` | `Get-Content -Encoding UTF8 \| ConvertFrom-Csv`；追加行手动拼 CSV |
| `Get-CimInstance` | `Get-WmiObject` |
| `-shr` / `-shl` | `[math]::Floor($x / 65536)` 之类算术 |
| `[pscustomobject]@{}` | `New-Object PSObject -Property @{}` |
| `-in` / `-notin` | `-contains` / `-notcontains` |
| `$x = if (...) {...} else {...}` | 先赋初值再 `if` 语句块 |
| `[string]::IsNullOrWhiteSpace()` | `$s -eq '' -or $s -eq $null` |
| `$PSScriptRoot` | `Split-Path -Parent $MyInvocation.MyCommand.Path` |

其他要点：
- 所有 `.Count` 的来源都要用 `@()` 包装（PS2 里单个对象没有 Count 属性）
- `Add-Type -AssemblyName System.Windows.Forms` 和 `-TypeDefinition` 在 PS2 可用
- 依赖系统自带 .NET（Win7 自带 3.5 够用），**不需要管理员权限**
- ps1 必须存成 **UTF-8 with BOM + CRLF**，否则 PS2 按 ANSI 解析、中文全乱；
  bat 内容保持纯 ASCII（cmd 按 GBK 解析 bat，写中文会乱）

## 已知坑

1. **`%~dp0` 不能直接做参数**：bat 里写 `-BaseDir "%~dp0"` 时，末尾反斜杠会把结束引号转义成
   字面引号，路径变成 `...\目录"\截图`，报"路径中具有非法字符"。
   正解：**bat 不传路径，脚本用 `$MyInvocation.MyCommand.Path` 自定位**；
   脚本里再加 `Trim().Trim('"').TrimEnd('\')` 兜底。
2. **`productState` 判断防护/病毒库状态不可靠**：Win11 Defender 返回 `0x060100`，
   与老资料的 `0x10/0x11` 编码不符，硬判断会把正常机器误标成"病毒库过期"。
   只记杀软名称，病毒库版本以截图为准（截图里要能看到版本或更新时间）。
3. **wmic 的 SecurityCenter2 只报注册到安全中心的杀软** —— 装了火绒的机器可能只报 Defender，
   所以查杀工具必须允许手动输入。
4. **字段里的换行会撑坏 CSV** —— 写台账前把 `\r\n` 替换成空格。
5. **截图失败就不写台账**，避免留下"有记录无证据"的空行。

## 现场作业安排

**串行做不完**。机械盘老机器全盘 40–90 分钟/台，80 台串行是十几个工作日。

正确做法：**逐台启动扫描后立即走人，绝不在机器前等**。
- 启动 80 台约 1 小时，收结果+截图约 1 小时；扫描时间由并行覆盖掉，一天可完成
- 按楼层/部门分片推进：启动完 A 片直接去 B 片，回头再从 A 片第一台开始收结果
- 按门牌号排序的清单（纸质）现场最顺手，勾选加备注

**必须提前跟客户打招呼**（最容易翻车）：
- **关掉睡眠和屏保** —— 睡眠会中断扫描；锁屏会让截图拍到黑屏，那一台白做
- 老笔记本别合盖
- 提醒各部门今天有人会动电脑，别锁屏走人

**可能大幅缩小范围**：去翻防火墙那条封禁策略的**命中日志**。
日志里尝试外连控制 IP 的内网源地址，就是中了木马的机器。
能定位到具体几台，其余就从"重点处理"降成"常规全盘"。

## 备选：客户现场不让插 U 盘

改用**手动登记的 Excel**：从客户已有的电脑统计表带出门牌号、部门、使用人、网络类型、
IP、MAC 六列并预填好，留下「查杀工具」「检测结果」「处置结果」给现场手填，
后两列做成下拉框。

**顺手把无线设备的两套密码挖出来**：客户的电脑统计表里，AP/路由器行的 `hostname`
经常被拿来记密码，格式是 **`WIFI:<WiFi密码>管理:<后台管理密码>`**，
例如 `WIFI:Xbl*101*管理:Lf_13579` —— 前面那截 `Xbl*101*` 是 **WiFi 密码**（跟着房间号走），
后面那截 `Lf_13579` 是**后台管理密码**（往往全场统一）。
⚠️ 别把前半截当成 SSID，这两者是不同的东西。
解析出来**分两列**填好（WiFi 密码一列、备注列放管理密码），现场连 WiFi、调 AP 都用得上。
判据要按 **hostname 特征**走，不要只认"使用人列写着 TP-LINK"——
这一批里使用人列还混着"锐捷""荣耀""tplink"，同一个品牌被写成了四种样子。

表要同时满足两种用法：能在电脑上点选，也能打印出来手写。
所以：表头加粗 + 浅底纹 + 居中、首行冻结、细边框、列宽按 A4 横向配、
门牌号列设成**文本格式**（否则"二楼大厅"这类文本和纯数字门牌会被 Excel 自动转格式）。
打印方向编辑器没有接口可设，要提醒用户在 Excel 里选「页面布局 → 纸张方向 → 横向」。

### 生成带下拉框的本地 xlsx：要绕两道弯

1. **表格子代理建不了新文件**。它只能往"已打开的工作簿"里写，把不存在的路径当 file_id
   传进去只会报 `No workbook open`，它也没有本地写盘能力。
   **正解**：先用本地编辑通道的 `create_sheet` 建空白工作簿 →
   `save_file file_id=<新建返回的id> file_path=<目标路径>` 把文件落到磁盘 →
   **再**让子代理往这个已存在的文件里写数据与格式。
2. **子代理的数据验证接口在本地 xlsx 上不可用**（`setDataValidation is not supported
   in local (xlsx) mode`，只支持在线文档）。下拉框必须用 **openpyxl 直接写**：

   ```python
   from openpyxl.worksheet.datavalidation import DataValidation
   dv = DataValidation(type='list', formula1='"发现木马,未发现异常"', allow_blank=True)
   ws.add_data_validation(dv)
   dv.add('H2:H83')
   wb.save(path)
   ```

   openpyxl 加载再保存后，表头样式、填充、对齐、冻结、边框、列宽、文本数字格式
   **都会保留**，可以放心用。改之前先 copy 一份备份，改完读回校验一遍。
   注意 `showDropDown` 语义是反的（`True` 表示**隐藏**箭头），不设该属性即可。
3. **写 xlsx 之前先确认文件没被 Excel 打开**。目录里出现 `~$<文件名>.xlsx` 锁文件即为占用，
   直接写会报 `PermissionError: [Errno 13]`。定位占用者：
   `Get-Process | Where-Object { $_.ProcessName -match '^(EXCEL|wps|et)$' }`。
   `editor_sdk` 自己的实例占用可以用 `close_file` 释放（先 `get_pool_status` 拿 file_id）；
   **Excel 占用只能请用户手动关** —— 不要强杀 `EXCEL.EXE`，会丢用户未保存的改动。
