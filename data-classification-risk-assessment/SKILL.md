# 数据分类分级与数据安全风险评估 工作流

## Overview

给单位（政务/企业）做数据分类分级 + 数据安全风险评估报告的可落地工作流。解决两个核心问题：①纠正分类分级自动化工具的过度分类结果；②从数据资产到风险评估报告的全链路产出。产出一套留痕物：分类分级清单 → 差距分析 → 整改建议清单 → 风险评估报告 →（视要求）整改通知单 + 复核。

## 触发场景

- 用户拿着工具扫描导出的「数据资产清单.xlsx + 分类分级清单.xlsx」，说"分类结果有问题 / 过度分类 / 不靠谱"
- 用户要做数据分类分级、出敏感字段清单、出分类分级清单
- 用户要做数据安全风险评估报告、分级防护差距分析、整改建议清单

## 工作流（6 步）

### 1. 获取数据资产

- 用户提供 SQL 数据库结构，或数据库设计文档（设计文档优先，字段描述更权威，能补上工具抽不到的描述）
- 用户用自动化分类分级工具扫描，导出两张 excel：数据资产清单（含中文字段描述、表描述）、分类分级清单（工具自动分类结果）

### 2. 重分类（纠正工具的过度分类）

- 工具导出的分类结果常拿英文字段名硬猜，导致过度分类（如把 delete_flag/create_time 判成"医疗健康信息"，把 100% 字段判成"个人信息"）
- **先建该单位的敏感词字典（必做）**：通用词典只能兜底，不同单位（医疗/教育/车管/交通…）字段差异大，不可能一套词覆盖所有单位。做法：粗跑一遍 → 看漏判/误判 → 把该单位业务敏感词补进脚本顶部词典 → 重跑
- 运行 `scripts/classify_data.py`：基于「中文字段描述 + 表描述」做敏感词词典匹配，产出：
  - `分类分级清单-修正版.xlsx`（全量字段四级重分类，行按级别上色：一级白 / 二级浅黄 / 三级浅红 / 四级深红）
  - `敏感字段清单-待人工确认.xlsx`（仅三级+四级，供人工逐条确认）
- 用法：`python classify_data.py [输入数据资产清单.xlsx] [输出前缀]`
- 人工过一遍敏感字段候选这步不能省（脚本是规则匹配，会有边缘误判）

### 3. 定分级框架（固定四级）

一级不敏感 / 二级低敏感 / 三级敏感 / 四级高敏感。

- 一级：时间戳、id、标志位、统计数（无个人信息、可公开）
- 二级：一般业务数据（车型/费用/流程/单位名）
- 三级：敏感个人信息（手机号/姓名/车牌/邮箱/住址）
- 四级：强身份/生物识别/鉴权（身份证/驾驶证/密码/人脸底库/银行卡）

关键口径：敏感个人信息（个保法，管个人权益）≠ 重要数据（数安法，管公共利益）。委办局/一般单位数据基本是"一般数据"内部按敏感度分四级，不涉及"核心/重要数据"，别把敏感字段升级成"重要数据"。

### 4. 现状核查 + 差距分析

- 从 `references/数据安全评估模板-默认版.md`（40 项检查库）按该单位数据实际**挑适用项**，生成针对性核查表（通常 12~16 项，砍掉 App/数据出境/爬虫等不适用的）
- 核查现状：技术测试（渗透/抓包/连库 select）+ 文档核查 + 人员访谈
- 差距分析：现状 vs 应然

### 5. 产出物（结构见 references/产出物模板规范.md）

- `分级防护差距分析表.xlsx`（现状/应然/差距/风险等级）
- `分级防护整改建议清单.xlsx`（R-01~R-0N，借鸿泰 8 列格式）
- `数据安全风险评估报告`（精简版 4 块：概述 / 分类分级结果 / 差距分析 / 风险结论+整改建议）

### 6. 闭环（视检查要求，可跳过）

- 整改通知单（留痕核心）+ 复核记录

## 关键口径

- 制度是**单位级**（分类目录 + 分级方法 + 防护措施，覆盖全单位数据版图），清单是**系统级**（逐系统逐库扫字段定级）
- 风险评估报告 = 差距分析表，**同一个东西只做一份**，别做两份
- 制度三段：附件1分类目录（单位定制）、附件2分级方法 + 附件3分级管控（跨单位复用通用版，参照生态环境规范）
