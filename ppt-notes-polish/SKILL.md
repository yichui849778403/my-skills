# PPT 备注口语化润色

目标：让备注念起来顺口、不拗口、不像在朗读。

用户风格核心：**用自然的说话节奏把意思讲清楚。** 受众多为委办局，自然但不随意。

## 备注 = 完整台词（已由用户确认）

用户的 PPT 备注就是现场照着念的完整台词，不现场发挥。润色方向：**缩"无信息的词"，不缩"有信息的内容"。**

**要缩（去掉后意思不变、念起来更顺）**：
- 不加分的形容词："严格的技术隔离" → "技术隔离"（"严格"这种去掉不影响的就删）
- 累赘动词/语气助词："进行排查" → "排查"、"开展调查" → "调查"
- 长词换短词："这起事件" → "这件事"、"完成了操作" → "做完操作"
- 书面套话：首先/其次/最后 → 删或换"先/再/然后"，因此 → 所以

**不缩（信息本体，删了意思就变）**：
- 操作步骤细节："拔主机箱后面的网线"、"不要重启或关机"
- 案例事实、关键限制条件、因果关系
- 技术术语

## 触发场景

- 用户要求改 PPT 备注、润色备注、口语化备注
- 备注读起来太棒读、不够自然
- 安全培训、技术培训等需要念稿的场景

## 交付方式 —— 只给文本，不碰 PPT 文件

**禁止通过编辑器 SDK 直接写入用户 PPTX 文件。** 用户反馈过：直接编辑并保存会导致 PPT 正文（图标、文字、样式）损坏。

正确流程：
1. 拿到备注原文（用户粘贴，或用户给文件后用只读方式提取）
2. 逐页给出"原文 vs 建议"，等用户确认
3. 最终按页码输出纯文本清单，用户自己粘贴进 PowerPoint

## 结构性规则（稳定，必须遵守）

1. **因果要接上**。两句之间有逻辑关系时不能硬切，缺连接词会"没头没脑"。比如"用另一台电脑改密码"必须带出"因为当前电脑可能已被控制"。
2. **列举序号不能删**。"第一类/第二类"、"第一步/第二步"这类序号删掉反而让内容不连贯、稀碎。保留序号，但措辞可以口语化。
3. **段落不能太碎**。步骤类内容拆成一句一段会像念说明书，应适当合并成叙述流。
4. **句尾要收住**。举例、分析完要有收尾句回扣主题，不能戛然而止。
5. **度：不棒读，也不聊天**。太书面像念稿，太口语（"你看""照样""所以你看"）又显随意。拿不准时往正式方向靠一点。
6. **流畅优先于短**。机械压缩会变成新的棒读。动笔前先理清原文的逻辑结构（几种做法、几个层面），组织时保持结构清晰。
7. **去条目感**。"标题冒号内容"的平行块念起来像念卡片清单，多条并列页要用"先是/再是/还有/最后"这类自然过渡词串联，把"列"变成"讲"。

## 常规润色手法

### 视觉空格 —— 念稿的锚点

在句子中插入空格，拆成 1-3 字的小块，作为念稿时眼球的落点。念错可以随口替换。

- 动宾之间："进行 整改"、"纳入 审批流程"
- 修饰词与中心词之间："临时 测试账户"、"统一的 密码策略"
- 术语两侧："弱口令"、"撞库手段"、"横向渗透"
- 主谓之间："攻击者 会利用"

用户已有的空格不要删。宁可多加不少加。

### 去"棒读感"

清单式过渡词让人感觉在朗读：

- 首先/其次/最后 → 删掉，或换成更轻的"先/再/然后"
- 因此 → 所以
- 这意味着 → 也就是
- 以及 → 还有
- 然而 → 但

### 口语化 + 缩冗余

- 书面词换口语词："记录下来" → "记下来"、"以此实现" → "靠这种方式"、"并非是" → "不是"
- 长句拆顺，逻辑不变
- 砍不加分的形容词、累赘词（见上方"要缩"清单）
- 操作步骤、关键细节、案例事实一个都不能少（见上方"不缩"清单）

## 禁止做的

- 不加"吧/嘛/呢"等语气词、"你得/咱们"等过度口语化人称
- 不在句尾加带态度的收尾（"多一点都不给"之类）
- 不改变原文逻辑顺序和实质内容
- 不改动技术术语
